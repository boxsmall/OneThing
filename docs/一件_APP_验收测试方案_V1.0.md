# 「一件」APP 验收测试方案

> 版本：V1.0  
> 平台：Android  
> 用途：研发自测、测试验收、发布回归  
> 发布门禁：P0 通过率 100%，无阻塞级或严重级未解决缺陷
> 开发决策修订：2026-09-02 · 本地签名 APK 发布 · 以《一件_APP_V1_开发决策基线.md》为准

---

## 1. 测试目标

验证 V1 是否真实满足以下产品承诺：

> 用户能够创建一件事、每天只完成一次、数据不丢、中断后还能继续、结束后历史仍然存在。

测试优先级：

1. 数据正确；
2. 状态正确；
3. 返回与恢复正确；
4. 提醒可控；
5. 视觉和动效一致。

---

## 2. 测试范围

### 2.1 包含

- 首次欢迎；
- 创建目标；
- 提醒开关与通知权限；
- 首页未完成、已完成和中断状态；
- 完成事务和防重复；
- 7 日进度和月历；
- currentStreak、totalCompleted、longestStreak、durationDays、gapDays；
- 设置和修改目标名称；
- 修改、关闭和恢复提醒；
- 结束目标、历史和下一件事；
- 杀进程、重启、跨天、时间和时区变化；
- NoOp Analytics、无网络权限和无数据上传；
- 云备份关闭与设备到设备迁移；
- 多尺寸、安全区和基本无障碍。

### 2.2 不包含

- 登录和云同步；
- 多目标并行；
- 补签和历史编辑；
- 社区、积分、AI；
- 数量型或计时型目标；
- 任何文字记录、备注、日记、图片或附件；
- 第三方 Analytics、Crash SDK、广告 SDK 和账号服务；
- 后续版本功能的兼容性。

| 层级 | 主要内容 | 执行方式 | 必须自动化 |
| --- | --- | --- | --- |
| 单元测试 | 日期、streak、duration、gap、状态推导 | JVM 测试 | 是 |
| 数据测试 | Room 唯一约束、事务、查询、迁移基础 | Instrumented / 数据库测试 | 是 |

| 发布回归 | P0/P1 全量 | Release 候选包 | P0 必须留记录 |

## 4. 测试环境矩阵

至少覆盖三档设备：

| 设备档位 | 建议条件 | 重点 |
| --- | --- | --- |
| 小屏 | 宽度小于或接近 360dp | 按钮、标题、月历和底部安全区 |
| 主流屏 | 360dp 基准、手势导航 | 主要视觉与完整流程 |
| 大屏 | 更宽或更高的手机屏幕 | 内容不过度拉伸、居中和留白 |

系统版本至少覆盖 API 26、API 36 和一台真实设备。主流视觉基准使用 360 × 800；所有可点击区域验收下限为 48dp × 48dp。

每档至少检查：

- 手势导航；
- 深色系统状态栏图标是否清晰；
- 默认字体大小；
- 较大字体缩放；
- 有网和无网，并确认 Release 均不产生应用网络请求；
- 通知权限允许和拒绝。

发布候选包必须使用 Release 或与 Release 等价的构建配置测试，不能只测 Debug 包。

# 6. 领域算法验收

## 6.1 currentStreak

| 编号 | 数据 | 预期 |
| --- | --- | --- |
| ST-01 | 无 Completion | 0 |
| ST-02 | 今天完成 | 1 |
| ST-03 | 今天、昨天、前天完成 | 3 |
| ST-04 | 今天未完成，昨天起连续 5 天完成 | 5，页面显示“已经连续完成 5 天” |
| ST-05 | 今天未完成，昨天也未完成 | 0 |
| ST-06 | 昨天漏掉，今天完成 | 1 |
| ST-07 | Completion 输入乱序且包含重复日期 | 去重排序后正确计算 |

唯一公式：

```text
今天已完成：从今天向前连续计算
今天未完成且昨天已完成：从昨天向前连续计算
今天和昨天均未完成：0
```

## 6.2 totalCompleted 与 longestStreak

| 编号 | 数据 | 预期 |
| --- | --- | --- |
| ST-08 | 3 个不同完成日期 | totalCompleted=3 |
| ST-09 | 同一日期重复输入 | 去重后只计 1 |
| ST-10 | 序列 3 天、断 1 天、再连续 2 天 | longestStreak=3 |
| ST-11 | 历史最长 3 天，中断后完成 1 天 | longestStreak 仍为 3 |
| ST-12 | 新连续序列达到 4 天 | longestStreak 更新为 4 |

## 6.3 durationDays

| 编号 | startDate | endDate / today | 预期 |
| --- | --- | --- | --- |
| DU-01 | 9 月 1 日 | 9 月 1 日 | 1 |
| DU-02 | 9 月 1 日 | 9 月 2 日 | 2 |
| DU-03 | 8 月 31 日 | 9 月 2 日 | 3 |
| DU-04 | 跨月、跨年 | 任意合法结束日 | LocalDate 差值 +1 |

禁止使用小时数除以 24 计算持续天数。

## 6.4 gapDays 与中断

| 编号 | 条件 | 预期 |
| --- | --- | --- |
| GP-01 | 今天新建，今天未完成 | ACTIVE_UNDONE，不进入中断 |
| GP-02 | 昨天完成，今天未完成 | ACTIVE_UNDONE，保留截至昨天的 streak |
| GP-03 | 昨天未完成，今天未完成 | ACTIVE_INTERRUPTED，gapDays=1 |
| GP-04 | 昨天和前天均未完成 | ACTIVE_INTERRUPTED，gapDays=2 |
| GP-05 | 创建后从未完成，已过去 3 个完整自然日 | gapDays=3，最早统计到 startDate |
| GP-06 | gapDays>1 后今天完成 | currentStreak=1，totalCompleted+1 |

# 7. P0 验收用例

## TC-P0-001 首次安装

前置条件：清除 App 数据。  
步骤：启动 App。  
预期：

- 只显示欢迎页；
- 不显示登录注册；
- 不弹通知权限；
- 点击“开始使用”进入创建页；
- 系统返回不重新进入欢迎页。

## TC-P0-002 创建目标

步骤：输入“走路 20 分钟”，保持提醒开启，点击“开始坚持”。  
预期：

- Goal 成功保存且 status=ACTIVE、activeSlot=1；
- startDate 为本地 today；
- 进入首页未完成；
- 创建页不在返回栈中；
- 杀进程重开仍存在该目标。

## TC-P0-003 非法目标与无文字记录

步骤：分别输入空字符串、纯空白、换行和超过 20 个用户可见字符的内容，并检查创建与完成流程。
预期：输入按规则被限制或“开始坚持”不可提交，数据库无非法 Goal；应用不存在备注、文字记录、日记、图片或附件入口和字段。

## TC-P0-004 完成一次

步骤：点击“我完成了”。  
预期：

- 只插入一条当天 Completion；
- 成功 Overlay 出现；
- 约 1.2 秒或点击后关闭；
- 首页进入已完成状态；
- AnalyticsTracker 可以被调用，但 Release NoOp 不上传任何事件或数据。

## TC-P0-005 重复完成

步骤：完成后重复点击、快速连点、重新进入首页。  
预期：

- 不再显示完成按钮；
- `(goalId, date)` 仍只有一条记录；
- totalCompleted 不重复增加。

## TC-P0-006 杀进程恢复

步骤：完成后强制结束 App，再启动。  
预期：仍为首页已完成状态，统计和月历不丢失。

## TC-P0-007 跨天

步骤：使用测试 DateProvider 或测试环境进入次日，恢复 App。  
预期：

- todayCompleted=false；
- 首页进入新一天未完成状态；
- 昨日 Completion 保留；
- 7 日进度日期窗口更新。

## TC-P0-008 连续递增

步骤：连续 3 个自然日分别完成。  
预期：currentStreak=3、totalCompleted=3、longestStreak=3。

## TC-P0-009 中断后完成

步骤：前三天完成，第 4 天不完成，第 5 天完成。  
预期：第 5 天完成后 currentStreak=1、totalCompleted=4、longestStreak=3。

## TC-P0-010 记录月历

步骤：准备包含完成和未完成日期的数据，打开记录页并切月。  
预期：

- 已完成、未完成、今天状态与 Completion 一致；
- 切月不修改数据和统计；
- 返回原首页状态。

## TC-P0-011 结束目标

步骤：设置 → 结束这件事 → 确认。  
预期：

- Goal.status=ENDED；
- endDate 为本地 today；
- Completion 保留；
- 未来提醒取消；
- 进入结束结果；
- 返回不能进入旧 ACTIVE 首页。

## TC-P0-012 开始下一件事

步骤：旧目标当天完成后结束，在结束结果页点击“开始下一件事”，创建并完成新目标。
预期：

- 清除结束流程返回栈；
- 新 Goal 使用新 goalId；
- 新旧 Completion 不串；
- 旧、新 Goal 可以各有一条当天 Completion；
- 旧目标仅出现在历史。

## TC-P0-013 通知权限拒绝

步骤：创建时保持提醒开启，拒绝通知权限。  
预期：

- 目标正常创建；
- reminderEnabled=false；
- 不建立提醒；
- 设置页显示提醒未开启；
- App 不崩溃。

## TC-P0-014 关闭提醒

步骤：设置页关闭提醒。  
预期：立即取消已调度任务，后续不再触发。

## TC-P0-015 安全区

步骤：在三档设备和手势导航模式打开全部页面。  
预期：顶部不与状态栏重叠，底部按钮不被手势区遮挡。

## TC-P0-016 返回逻辑

步骤：逐页执行系统返回。  
预期：

- 不回到已完成的欢迎页或创建页；
- 记录返回原首页状态；
- 设置返回首页；
- 结束后不能返回 ACTIVE 首页。

## TC-P0-017 提醒默认值

步骤：打开创建页。  
预期：提醒默认开启，时间默认 20:00。

## TC-P0-018 创建时关闭提醒

步骤：关闭提醒后创建目标。  
预期：不申请通知权限，目标创建成功，不建立提醒。

## TC-P0-019 连续天数展示

前置数据：昨天及此前连续完成，今天未完成。  
预期：currentStreak 保留截至昨天的值，文案使用“已经连续完成 N 天”。

## TC-P0-020 多日中断

步骤：连续漏掉多天后打开 App，再完成今天。  
预期：

- 进入 ACTIVE_INTERRUPTED；
- gapDays 正确；
- gapDays>1 使用多日中断文案；
- 不突出连续 0 天；
- 完成后 currentStreak=1。

## TC-P0-021 持续天数

步骤：分别测试当天创建并结束、跨日和跨月结束。  
预期：durationDays=首尾 LocalDate 差值+1，最小为 1；与 totalCompleted 分开展示。

## TC-P0-022 提醒恢复

步骤：分别模拟手机重启、系统时间变化、时区变化和 App 更新。  
预期：

- 只为 ACTIVE 且 reminderEnabled=true 的目标重调度；
- 无重复提醒任务；
- ENDED 或关闭提醒的目标不恢复。

## TC-P0-023 历史返回

步骤：分别从设置和结束结果进入历史。  
预期：系统返回分别回到设置和结束结果；不能回到 ACTIVE 首页。

## TC-P0-024 无 ACTIVE 通知点击

步骤：结束目标后通过残留或测试通知入口启动 App。  
预期：进入创建页，不恢复、不修改已结束目标。

## TC-P0-025 无数据上传

步骤：检查 Release 依赖树和 Manifest；分别在有网、无网环境执行创建、完成、记录和结束流程并观察网络。
预期：

- Release 使用 NoOpAnalyticsTracker；
- 不包含第三方 Analytics、Crash、广告或账号 SDK；
- Release Manifest 不声明 INTERNET 权限；
- 不生成或上传安装标识、行为、设备信息和用户输入；
- 有网和无网时核心功能均正常，业务数据完全保存在本地。

# 11. 视觉与交互检查

逐页检查：

- [ ] 页面背景为统一暖白色；
- [ ] 主文字、次级文字、黄色和绿色状态色使用统一 Token；
- [ ] 页面左右边距保持统一；
- [ ] 主按钮高度和圆角一致；
- [ ] 首页未完成与已完成结构基本稳定；
- [ ] 返回、齿轮、箭头等热区至少 48dp；
- [ ] 目标标题过长不破坏布局；
- [ ] 月历星期和日期对齐；
- [ ] 月历、状态点和统计卡片无重叠，开始日前和未来日期为中性空状态；
- [ ] 历史卡片完整显示第三行，无文字裁切；
- [ ] 各首页统一使用右上角齿轮，目标图标不存在空白方块或输入光标残留；
- [ ] 中断状态没有红色失败警告；
- [ ] 结束危险操作与“继续坚持”主操作区分明确；
- [ ] Overlay 不遮挡系统级返回或产生死锁；

# 12. 缺陷分级

| 级别 | 定义 | 示例 | 发布处理 |
