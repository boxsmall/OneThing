# 1. 产品背景

市面上的习惯类产品通常会不断增加目标、任务、分类、计划、统计、社区和激励体系，使用成本逐渐接近一个复杂的任务管理工具。

「一件」选择反方向：

> **不帮助用户同时管理很多目标，只帮助用户把现在最想坚持的一件事继续做下去。**

产品的核心不是“打卡”，而是：

> **今天有没有把这件事做完。**

因此 V1 要尽量降低操作成本，不要求用户写日记、上传图片、选择复杂计划，也不通过积分、排行榜等方式增加额外负担。

---

# 2. 产品定位

## 2.1 一句话定位

**一个帮助用户每天坚持一件小事的极简 App。**

## 2.2 核心原则

1. **一次只坚持一件事。**
2. **一天只需要记录一次。**
3. **日常操作尽量控制在 3 秒内。**
4. **首次创建目标尽量控制在 30 秒内。**
5. **中断不否定之前的积累。**
6. **记录真实，不提供补签。**
7. **先保证状态正确，再考虑复杂体验。**
8. **凡是不能直接帮助用户今天完成这件事的功能，V1 不做。**

## 2.3 典型目标示例

- 每天走路 20 分钟
- 每天读书 30 分钟
- 每天背单词
- 每天拉伸
- 每天 11 点前睡觉

V1 只支持：

> **“每天完成一次”类型的目标。**

暂不支持计数型、计时型、“坚持不做某件事”等其他模式。

# 3. 用户与使用场景

## 3.1 目标用户

有一件希望每天坚持的小事，但不希望使用复杂习惯管理、任务管理或日记类产品的用户。

## 3.2 核心用户需求

用户需要解决的不是“管理很多事情”，而是：

- 我现在最想坚持什么？
- 我今天做了没有？
- 我已经坚持多久？
- 中断以后还能不能继续？
- 这段坚持最终留下了什么记录？

## 3.3 核心场景

### 场景 A：首次创建

用户安装 App 后，输入：

> 走路 20 分钟

设置每天提醒时间，例如：

> 20:00

点击“开始坚持”，进入首页。

### 场景 B：每天完成

用户打开 App：

> 今天 → 走路 20 分钟 → 我完成了

点击一次即可记录。

### 场景 C：查看坚持情况

用户进入“查看记录”，看到：

- 当前连续
- 累计完成
- 最长连续
- 月历完成记录

### 场景 D：发生中断

用户昨天没有完成。

今天进入 App 时，不使用失败、惩罚或责备文案，而是告诉用户：

> 昨天没有完成。  
> 今天继续。

今天再次完成后，新的连续天数从 1 开始，但累计完成和历史最长连续继续保留。

### 场景 E：结束一件事

用户认为当前目标已经完成阶段使命，可以主动：

> 结束这件事

系统保存完整历史，并允许：

> 开始下一件事

# 4. V1 产品目标

## 4.1 产品目标

V1 只验证一个核心假设：

> **当产品足够简单时，用户是否愿意每天回来记录并继续坚持同一件事。**

## 4.2 V1 核心闭环

```text
创建一件事
    ↓
每天完成
    ↓
查看记录
    ↓
中断后继续
    ↓
结束这件事
    ↓
开始下一件事
```

## 4.3 未来产品判断指标

以下指标仅作为未来公开版本候选。V1 本地发布版不采集、不上传这些指标，也不预设硬阈值；可在自愿的本地测试记录中人工评估。

| 指标 | 定义 |
| --- | --- |
| 创建转化率 | goal_create_success / 首次进入创建流程用户 |
| 首日完成率 | 创建目标当天发生 complete_success 的用户比例 |
| D1 回访率 | 创建目标用户中，次日再次打开 App 的比例 |
| 7 日完成天数 | 创建后前 7 个自然日中的完成去重天数 |
| 7 日仍在坚持率 | 第 7 日仍有 ACTIVE 目标，且近期存在打开或完成行为 |
| 提醒点击率 | reminder_click / 实际发出的提醒 |

# 8. 功能详细需求

## 8.1 欢迎页

### 出现条件

仅首次安装、首次使用时出现。

已经完成欢迎流程后，再次打开 App 不再进入欢迎页。

### 页面内容

- 产品标识“1.”
- 产品名“一件”
- 产品理念“一次，只坚持一件事。”
- 主按钮“开始使用”

### 交互

点击：

> 开始使用

进入创建目标页。

### 规则

- 不显示登录。
- 不显示注册。
- 不在欢迎页立即申请通知权限。
- 系统返回不能反复进入已经完成的欢迎流程。

---

## 8.2 创建目标

### 页面目的

让用户尽可能快地建立当前唯一目标。

### 页面内容

标题：

> 你想坚持什么？

输入区域：

> 我想每天  
> [ 走路 20 分钟 ]

提醒区域：

> 提醒我　开 / 关  
> 每天　20:00

提醒默认开启，默认时间为 20:00。用户关闭提醒后，隐藏或禁用时间选择。

主按钮：

> 开始坚持

可提供轻量示例：

- 读书 30 分钟
- 走路 20 分钟
- 11 点前睡觉

### 业务规则

1. 当前同时最多存在一个 ACTIVE 目标。
2. 目标名称必填。
3. 目标名为单行文本，最多 20 个用户可见字符；提交前去除首尾空白，不允许纯空白或换行。
4. 空目标时“开始坚持”按钮不可用。
5. V1 不需要选择目标分类、颜色、难度、结束日期等。
6. 创建成功后进入首页未完成状态。
7. 创建成功后系统返回不能回到创建页重新重复创建。
8. 没有 ACTIVE 目标且存在历史目标时，创建页底部显示弱入口“查看过去的坚持”。
9. “走路 20 分钟”只作为 placeholder，不预填为用户的目标。
10. 允许中文、英文、数字、内部空格和 Emoji。

### 提醒权限

如果用户开启提醒：

1. 保存目标；
2. 目标保存成功后再检查/申请通知权限；
3. 权限被拒绝不影响目标创建；
4. 权限拒绝后，将 reminderEnabled 置为 false，仅提醒功能不可用；
5. 用户关闭提醒时不申请通知权限，也不建立提醒。
6. 如果用户创建目标时当天提醒时间已经过去，首次提醒安排在次日，不补发过期通知。

---

## 8.3 首页·未完成

### 出现条件

存在 ACTIVE 目标，且当天没有完成记录。

### 页面内容

- 当前日期
- 设置入口
- “今天”
- 当前目标名称
- 目标图标
- 当前连续天数
- 7 日完成进度
- “我完成了”主按钮
- 辅助文案“今天只做好这一件事”
- “查看记录”

7 日进度固定展示“过去 6 天 + 今天”，从旧到新排列。目标开始日前的日期使用中性空状态，不算未完成。今天尚未完成时，currentStreak 只计算到昨天；完成落库后才把今天计入。

### 核心操作

用户点击：

> 我完成了

系统必须：

1. 检查当天是否已经存在完成记录；
2. 若不存在，则写入 Completion；
3. 更新连续/累计/最长连续统计；
4. 调用 AnalyticsTracker；Release NoOp 不上传数据；
5. 进入完成反馈；
6. 最终进入首页已完成状态。

### 防重复要求

同一目标、同一自然日：

> 最多只能存在一条 Completion。

UI 层防抖，数据层同时建立唯一约束。

---

## 8.4 完成反馈

### 页面目的

给用户非常轻量的完成感，不增加额外操作。

### 内容

- 绿色成功图形
- “今天完成”
- “连续第 N 天”
- 简短鼓励文案，例如“明天继续。”

### 交互

- Completion 成功落库后，在首页上方显示临时成功覆盖层；
- 覆盖层不是独立业务路由，不进入页面返回栈；
- 约 1.2 秒后自动关闭，首页呈现已完成状态；
- 用户也可以点击覆盖层立即关闭；
- 数据写入失败时不得播放成功反馈，也不得产生 Debug 成功事件。

### 动效原则

成功 Overlay 的状态与交互属于 P0；触觉、缩放、淡入和对勾动画属于 P1，不得因动画未完成而阻塞数据库状态闭环。

可以有：

- 轻触觉反馈
- 按钮轻微缩放
- 成功卡片淡入
- 对勾轻量动画

不做：

- 金币
- 积分
- 烟花式强动画
- 多步骤奖励弹窗

---

## 8.5 首页·已完成

### 出现条件

存在 ACTIVE 目标，且当天已有 Completion。

### 页面内容

首页整体布局保持稳定，仅状态变化：

- 目标名称不变
- 黄色未完成主色切换为绿色完成色
- 显示绿色对勾
- “今天已完成”
- “连续第 N 天”
- 7 日进度更新
- 可显示极轻鼓励卡片
- “查看记录”

### 规则

当天完成以后：

- 不再显示“我完成了”按钮；
- 不允许重复增加完成次数；
- 杀进程重新打开后仍保持已完成状态。

---

## 8.6 坚持记录

### 页面目的

让用户快速知道：

> 我坚持得怎么样。

### 页面内容

#### 月历

状态包括：

- 已完成：绿色实心点
- 未完成：空心点
- 今天：绿色描边/双层高亮

月历以周一为一周起始日，使用 7 列自适应网格。目标开始日前、目标结束日后和未来日期使用中性空状态；日期、状态点和下方统计卡片不得重叠。

#### 三个核心数据

- 当前连续
- 累计完成
- 最长连续

#### 目标信息

- 开始日期
- 当前正在坚持的目标

### 业务规则

1. 月历数据必须来自真实 Completion。
2. 切换月份不修改任何统计数据。
3. V1 不支持补签。
4. 返回后回到进入记录页之前的首页状态。

---

## 8.7 中断后首页

### 出现条件

同时满足：

1. 存在 ACTIVE 目标；
2. 目标不是今天新建；
3. 今天尚未完成；
4. 昨天没有 Completion。

统一使用 ACTIVE_INTERRUPTED 状态，并计算 gapDays：从昨天向前连续统计未完成的自然日数，最早统计到 startDate；如果从未完成过，则从 startDate 统计至昨天。连续漏掉多天时不增加新的状态类型。

### 产品原则

中断是真实记录，但不能把此前的全部努力视觉上清零。

页面不使用：

- “失败”
- 红色大面积警告
- 惩罚
- 强负面表达

### 推荐内容

例如：

> 昨天没有完成。  
> 过去 37 天，你完成了 36 天。  
> 今天继续。

如果 gapDays > 1，改为：

> 有几天没有继续了。  
> 今天回来就好。

### 业务规则

如果用户今天完成：

- 新的 currentStreak = 1；
- totalCompleted + 1；
- longestStreak 保留历史值；
- 只有未来新的连续记录超过 longestStreak 时才更新。

中断页不突出“连续 0 天”，优先展示累计完成和历史最长连续。

## 8.8 设置

### 页面内容

当前坚持：

> 走路 20 分钟

提醒：

> 每天 20:00

提醒通知：

> 开 / 关

其他：

- 我的历史
- 结束这件事
- 关于一件
- 隐私政策

### 功能规则

#### 修改提醒时间

保存新时间后：

1. 取消旧提醒；
2. 建立新的提醒。

#### 关闭提醒

立即取消当前目标未来提醒。

#### 修改目标名称

可修改当前目标名称，但：

- 不能产生新 Goal；
- 历史 Completion 仍属于原 goalId；
- 不重置开始时间与统计。

---

## 8.9 结束这件事确认

### 页面目的

避免用户误操作终止当前目标。

### 页面内容

展示：

- 这件事持续了 N 天
- 累计完成 N 天
- 最长连续 N 天

操作：

> 继续坚持

> 结束这件事

### 规则

1. “继续坚持”为默认安全操作。
2. “结束这件事”采用危险操作视觉。
3. 用户确认结束后：
   - Goal.status = ENDED
   - 写入 endDate
   - 取消当前目标所有未来提醒
   - Completion 全部保留
4. 结束后不能通过系统返回重新回到 ACTIVE 首页。
5. 持续天数按包含开始日和结束日的自然日计算：durationDays = endDate - startDate + 1，最小为 1。

---

## 8.10 结束结果页

### 页面目的

让一段坚持有明确结尾。

### 内容

正向总结：

> 你完成了一段坚持。

如果该目标累计完成天数为 0，改为：

> 这段记录已保存。

并展示：

- 目标名称
- 持续天数
- 完成天数

主按钮：

> 开始下一件事

次级入口：

> 查看我的历史

### 交互

“开始下一件事”进入创建目标页。

新目标与旧目标的数据必须完全隔离。

点击“开始下一件事”后清除结束流程返回栈，不能返回结束结果或已结束目标首页。

---

## 8.11 我的历史

### 页面目的

保存用户曾经坚持过的目标，而不是目标结束即消失。

### 列表内容

每个历史目标展示：

- 目标名称
- 起始日期
- 结束日期
- 持续天数
- 完成天数

### V1 规则

- 只展示已结束目标。
- 不做复杂筛选。
- 不做排行榜。
- 不提供“清空历史”功能。
- V1 点击历史条目可以暂不提供复杂详情页。
- 从设置进入历史，系统返回设置；从结束结果进入历史，系统返回结束结果。
- App 重启且没有 ACTIVE 目标时进入创建页；若存在历史目标，可从创建页弱入口再次进入历史。
- 历史列表按 endDate 倒序；同日结束按创建时间倒序。
- 卡片高度必须自适应，完整展示名称、起止日期、持续天数和完成天数。

# 9. 产品状态机

## 9.1 顶层状态

| 状态 | 定义 |
| --- | --- |
| NO_GOAL | 没有当前 ACTIVE 目标 |
| ACTIVE_UNDONE | 有 ACTIVE 目标，今天尚未完成 |
| ACTIVE_DONE | 有 ACTIVE 目标，今天已经完成 |
| ACTIVE_INTERRUPTED | 有 ACTIVE 目标、目标非今天新建、昨天未完成且今天尚未完成；可附带 gapDays |
| ENDED | 当前目标已结束 |

## 9.2 状态转换

```text
首次使用
  ↓
NO_GOAL
  ↓ 创建目标
ACTIVE_UNDONE
  ↓ 完成今天
ACTIVE_DONE
  ↓ 次日
ACTIVE_UNDONE

如果上一日未完成：
ACTIVE_UNDONE
  ↓ 跨天
ACTIVE_INTERRUPTED
  ↓ 完成今天
ACTIVE_DONE（currentStreak = 1）

任意 ACTIVE 状态
  ↓ 用户确认结束
ENDED
  ↓ 开始下一件事
NO_GOAL → 创建目标

App 重启且不存在 ACTIVE 目标：
NO_GOAL → 创建目标（存在历史时显示历史弱入口）
```

# 10. 连续天数与统计规则

## 10.1 todayCompleted

定义：

> 当前目标在今天是否存在 Completion。

## 10.2 totalCompleted

定义：

> 当前目标所有 Completion 的去重自然日数量。

中断不会清零。

## 10.3 currentStreak

连续自然日均存在完成记录时递增。

规则：

- 如果今天已完成，计算截至今天的连续完成天数；
- 如果今天未完成、昨天已完成，显示截至昨天的连续完成天数，文案使用“已经连续完成 N 天”；
- 如果今天未完成且昨天也未完成，currentStreak = 0，并进入中断状态；
- 中断后的下一次完成从 1 开始，完成后文案使用“连续第 1 天”。

示例：

```text
第1天 完成
第2天 完成
第3天 完成
currentStreak = 3

第4天 未完成

第5天 完成
currentStreak = 1
```

## 10.4 longestStreak

当前目标历史所有完成记录中，最长的连续自然日序列。

结束目标不会清空 longestStreak。

## 10.5 durationDays

目标持续天数按自然日计算，并包含开始日和结束日：

```text
已结束目标：durationDays = endDate - startDate + 1
进行中目标：durationDays = today - startDate + 1
```

durationDays 最小为 1，与 totalCompleted 分开统计。页面统一使用“持续 N 天”和“完成 N 天”，不能混用。

# 11. 日期与跨天规则

1. 以用户设备本地自然日为准。
2. 00:00 后进入新的一天。
3. App 在跨天时仍处于前台，重新回到前台或页面恢复时检查日期。
4. 如果 lastOpenedDate 与 today 不一致，重新计算当天状态。
5. V1 不支持补签。
6. V1 不做复杂系统时间防作弊。

# 12. 数据模型

V1 数据本地优先，不需要账号和云端后台。

## 12.1 Goal

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String / Long | 唯一 ID |
| name | String | 目标名称 |
| startDate | LocalDate | 开始日期 |
| endDate | LocalDate? | 结束日期 |
| status | ACTIVE / ENDED | 目标状态 |
| activeSlot | Int? | ACTIVE 时固定为 1，ENDED 时为 null |
| reminderEnabled | Boolean | 是否开启提醒 |
| reminderTime | LocalTime? | 提醒时间 |
| createdAt | DateTime | 创建时间 |
| updatedAt | DateTime | 更新时间 |

约束：

> `activeSlot` 建立唯一索引；ACTIVE Goal 的 activeSlot 固定为 1，ENDED 为 null，从数据库层保证同时最多一个 Goal.status = ACTIVE。

## 12.2 Completion

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String / Long | 记录 ID |
| goalId | String / Long | 所属目标 |
| date | LocalDate | 完成自然日 |
| completedAt | DateTime | 实际完成时间 |

唯一约束：

```text
goalId + date UNIQUE
```

允许同一天结束旧目标并创建、完成新目标；不建立跨 goalId 的全局日期唯一约束。

`currentStreak`、`totalCompleted` 和 `longestStreak` 从 Completion 真实记录计算，不保存派生缓存。Goal、Completion 和轻量非敏感设置允许设备到设备迁移，但关闭云备份；提醒任务和权限结果不迁移，恢复后重新检查和调度。

## 12.3 Settings

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| hasSeenWelcome | Boolean | 是否完成欢迎流程 |
| notificationPermissionState | Enum | UNKNOWN / GRANTED / DENIED |
| lastOpenedDate | LocalDate | 上次打开日期 |

# 13. 通知提醒需求

## 13.1 V1 提醒能力

每个 ACTIVE 目标只支持：

> 一个固定每日提醒时间。

提醒默认开启、默认时间为 20:00，用户可以在创建页或设置页关闭。V1 的产品承诺是“在所选时间附近提醒”，不承诺闹钟级分钟精确。

## 13.2 权限策略

不在 App 启动时立即请求权限。

当用户真正开启提醒时：

1. 检查通知权限；
2. 需要时请求；
3. 权限拒绝不影响目标使用，并将提醒状态置为关闭；
4. V1 不申请精确闹钟特殊权限。
5. 小米、Redmi、POCO 设备在提醒开启时，设置页显示“系统提醒保障”，说明开启系统自启动并将省电策略设为“无限制”，同时提供应用系统设置入口；不使用非公开接口伪造或读取厂商权限状态。

## 13.3 通知文案

标题：

> 今天那件事，做了吗？

正文：

> 走路 20 分钟

## 13.4 点击通知

直接进入当前 ACTIVE 目标首页。

如果不存在 ACTIVE 目标，进入创建页，不能恢复或修改已结束目标。

## 13.5 已完成后的处理

如果当天已经完成：

- 不再发当天剩余提醒；
- 不因为通知再次创建 Completion。

## 13.6 结束目标

结束目标时必须取消该目标全部未来提醒。

## 13.7 调度与系统变化

- 正常设备条件下，提醒验收容差为用户所选时间前后约 15 分钟；
- 厂商省电策略可能突破上述正常容差；对已识别的小米系设备必须提供可发现、可点击、支持大字体的自启动与省电策略引导，不把“Alarm 已登记”当作真实到点验收通过；
- 每次提醒触发后按目标的本地时间计算并安排下一次，避免周期任务持续漂移；
- 手机重启、系统时间变化、时区变化或 App 更新后，重新读取 ACTIVE 目标并调度提醒；
- 修改提醒时间时先取消旧任务再建立新任务；
- 关闭提醒或结束目标后不得重新调度。

# 15. Android 适配要求

P0 要求：

1. 使用安全区/WindowInsets 处理状态栏和底部手势区。
2. 360dp 为设计基准，不写死单机分辨率。
3. 小屏优先保证：
   - 任务标题
   - 连续天数
   - 7 日进度
   - 核心按钮
4. 所有可点击入口最小热区为 48dp × 48dp。
5. 文本不能因为字体缩放被固定高度裁切。
6. 小屏、主流屏、大屏至少三档走查。

# 16. Analytics 与网络决策

## 16.1 V1 已锁定原则

V1 不接入任何第三方 Analytics、Crash SDK、广告 SDK 或账号服务，不收集、不上传用户行为、目标内容、设备信息或随机安装标识。

- 保留 `AnalyticsTracker` 接口，Release 使用 `NoOpAnalyticsTracker`。
- Debug 构建可以输出仅本机可见的结构化日志，用于联调，不持久化为用户画像。
- 核心 Release Manifest 不声明 `INTERNET` 权限。
- Analytics 不属于 V1 发布验收项。

## 16.2 未来候选事件表（不进入 V1）

| 事件 | 触发时机 | 关键参数 |
| --- | --- | --- |
| app_open | App 进入前台 | has_active_goal, today_completed |
| welcome_start_click | 点击开始使用 | - |
| goal_create_success | 成功创建目标 | reminder_enabled, reminder_hour |
| home_view | 进入首页 | state, current_streak |
| complete_click | 点击我完成了 | current_streak_before |
| complete_success | 完成记录真实落库成功 | current_streak_after, total_completed |
| record_view | 打开坚持记录 | current_streak, total_completed |
| reminder_permission_result | 通知权限结果 | granted / denied |
| reminder_click | 点击系统提醒 | hour |
| goal_end | 结束目标 | duration_days, total_completed, longest_streak |
| new_goal_start | 创建下一目标 | previous_duration_days |

### 未来接入时的约束

`complete_success` 必须以真实 Completion 成功写入为触发条件。

不能：

> 用户只是点击按钮就直接上报 complete_success。

同时遵守：

- 不上传目标名称或其他用户输入内容；
- 埋点统一通过可替换的 AnalyticsTracker 接口封装；
- 未来事件必须异步、可丢弃且不得影响本地业务数据。
- 任何未来接入必须先更新隐私政策和发布验收口径，不得直接启用现有候选事件。

# 17. 异常与边界场景

| 场景 | 产品处理 |
| --- | --- |
| 目标为空 | 不允许创建 |
| 目标过长 | 限制长度，首页最多 2 行或按规则截断 |
| 通知权限拒绝 | 目标可正常使用 |
| 创建页关闭提醒 | 不申请通知权限，不建立提醒 |
| 重复点击完成 | 只允许生成 1 条完成记录 |
| App 杀进程 | 数据必须恢复 |
| 跨天 | 自动进入新一天状态 |
| 中断 | 连续重算，累计保留 |
| 结束目标 | 历史保留，不删除 Completion |
| 无历史 | 展示空状态 |

| 手机重启/时间或时区变化 | 重新读取 ACTIVE 目标并调度提醒 |
| 通知点击时无 ACTIVE 目标 | 进入创建页，不恢复旧目标 |

# 18. 非功能需求

## 18.1 性能

由于 V1 为本地轻量工具：

- 首页进入不依赖网络；
- 完成操作应立即反馈；
- 数据写入不能阻塞明显交互。

## 18.2 离线

核心功能必须完全离线可用：

- 创建目标
- 完成
- 统计
- 月历
- 历史
- 设置

## 18.3 数据持久化

以下场景不得丢失数据：

- App 退后台
- App 被杀
- 手机重启
- App 次日重新打开

## 18.4 隐私

V1 不要求账号登录，核心数据保存在本地，不向开发者或第三方上传。关闭系统云备份，仅允许设备到设备迁移。

设置页需提供：

- 关于
- 隐私政策

本地发布版内置离线隐私说明，至少说明不收集、不上传数据、设备到设备迁移范围和卸载后的数据行为。“关于一件”同时展示版本、Apache-2.0 许可证和 GitHub 项目地址。未来进入公开应用商店前再补充主体、联系邮箱和公开隐私政策 URL。

# 19. 验收标准

## 19.1 P0 产品验收

- [ ] 首次安装只进入欢迎页，无登录注册。
- [ ] 用户 30 秒内可完成目标创建。
- [ ] 每天记录可通过一次点击完成。
- [ ] 同一天不能重复增加完成次数。
- [ ] App 重启后数据不丢。
- [ ] 第二天自动进入新的未完成状态。
- [ ] 今天未完成但昨天已完成时，展示截至昨天的 currentStreak；昨天也未完成时 currentStreak = 0。
- [ ] 连续 3 天完成后 currentStreak = 3。
- [ ] 中断一天再完成后 currentStreak = 1。
- [ ] 中断不影响累计完成与历史最长连续。
- [ ] 月历与 Completion 数据一致。
- [ ] 结束目标后历史保留。
- [ ] 结束目标后未来提醒取消。
- [ ] 可以开始下一件事。
- [ ] 通知权限拒绝不影响核心功能。
- [ ] 创建页关闭提醒时不申请通知权限。
- [ ] 手机重启、系统时间或时区变化后，ACTIVE 目标提醒能重新调度。
- [ ] 持续天数按包含首尾日期的自然日计算，且与完成天数分开。
- [ ] 历史页按来源正确返回设置或结束结果；结束后不能返回 ACTIVE 首页。
- [ ] 所有系统返回行为正确。
- [ ] 所有页面不与 Android 状态栏/手势区冲突。

## 19.2 P1 体验验收

- [ ] 完成后存在轻量成功反馈。
- [ ] 完成反馈不影响快速退出。
- [ ] 首页未完成与已完成布局基本稳定，不出现明显跳变。
- [ ] 超长目标不造成严重裁切。
- [ ] 历史为空时有合理空状态。
- [ ] 多分辨率下视觉结构稳定。

V1 以本地签名 APK 方式发布，不接入应用商店。只有满足以下条件，V1 才进入发布：

> **用户能够创建一件事、每天只完成一次、数据不丢、中断后还能继续、结束后历史仍然存在。**

同时：

- P0 开发任务全部完成；
- P0 测试用例 100% 通过；
- Release 使用 NoOpAnalyticsTracker，不包含第三方 Analytics、Crash SDK、广告 SDK 或 `INTERNET` 权限；
- 连续天数统计经过跨天数据人工验证；
- 提醒的开启、拒绝、修改、关闭、结束目标场景全部验证；
- APK 使用仓库外固定密钥签名，并记录 Git commit 与 SHA-256；
- API 26、API 36 和至少一台真实设备完成核心回归；
- 不新增 V1 范围外功能。

# 22. 产品决策原则

开发、设计、测试遇到未覆盖问题时，按以下原则决策：

1. 能通过状态变化解决，就不新增页面。
2. 能通过默认规则解决，就不新增设置项。
3. 能本地解决，就不增加后台依赖。
4. 状态正确性优先于动画效果。
5. 简单优先于功能完整。
6. 用户中断以后允许继续，但不篡改历史。
7. 所有新增功能先回答：

> **它是否能直接提高用户今天完成这件事的概率？**

如果不能，V1 不加入。

---

> **「一件」V1 的产品边界：一次只坚持一件事，一天只完成一次。**

# 23. V1.1 品牌体验升级补充需求（2026-09-05）

V1.1 不扩大业务范围，只升级品牌识别和完成反馈：

1. 创建目标时提供走路、阅读、睡眠、喝水、拉伸、学习、吃药、其他 8 个图标；必须由用户明确选择，默认“其他”，不根据名称猜测。
2. 图标与目标一起本地持久化；设置页可修改当前目标，首页、记录页和历史卡片显示一致。旧数据升级后使用“其他”，目标名称、日期、Completion 和提醒保持不变。
3. 冷启动使用 Android 系统 SplashScreen，暖白背景与 A1 Logo，不增加广告、按钮、联网内容或第二个启动 Activity。
4. 点击“我完成了”后仍先保存 Completion；成功后播放 1.5–1.8 秒的 Logo 点亮动画。黄点沿不闭合半环运动、变绿并出现对勾，文案由真实连续天数生成。
5. 基础、连续 3/7/30 天可有轻量差异，但不得形成积分、奖励、彩带或游戏化反馈；Lottie 不包含中文文字。
6. 返回、切后台、进程重建、关闭系统动画或资源加载失败时，已完成状态不能回退，也不能重复写入；必须提供可用降级反馈。
7. TalkBack 只朗读一次完整完成信息，装饰轨迹和粒子不进入语义树；图标选中状态同时提供标签和语义，不只依赖颜色。
8. V1.1 仍完全不支持文字记录、备注、图片、账号、云同步、多目标、社交、广告或 Analytics，Release 仍不声明 `INTERNET`。

开发与非真机验收结果见《一件_APP_V1.1_品牌体验升级开发任务.md》和《一件_APP_本地发布记录_V1.1.0.md》。实体手机安装与正式覆盖升级按用户要求暂缓。
