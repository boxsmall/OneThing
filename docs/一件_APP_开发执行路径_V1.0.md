# 「一件」APP 开发执行路径

> 版本：V1.0  
> 平台：Android  
> 目标：把已经封板的产品规则转化为可安装、可测试、可发布的本地优先 MVP  
> 推荐技术基线：Kotlin / Jetpack Compose / Navigation Compose / Room / DataStore

---

## 1. 文档用途

本文用于回答三个问题：

1. 开发从哪里开始；
2. 每一阶段具体完成什么；
3. 达到什么条件才能进入下一阶段。

需求优先级按照以下文档执行：

1. 《一件_APP_产品需求文档_PRD_V1.0.md》：产品逻辑与业务规则；
2. 《一件_APP_前端调整与交互实现清单_V1.0.md》：页面、视觉和交互；
3. 《一件_APP_开发任务拆解与验收用例_V1.0.md》：任务、数据和验收口径；
4. 《一件_APP_验收测试方案_V1.0.md》：测试步骤、测试记录和发布门禁；
5. Figma：页面结构与视觉参考。

发生冲突时，不允许开发自行扩展产品范围；先按以上优先级收口。

---

## 2. 最终交付目标

V1 必须完成以下闭环：

```text
欢迎
→ 创建一件事
→ 首页未完成
→ 完成今天
→ 首页已完成
→ 查看记录
→ 中断后继续
→ 设置与提醒
→ 结束当前目标
→ 查看历史
→ 开始下一件事
```

发布前必须满足：

- 同时最多一个 ACTIVE 目标；
- 同一目标同一自然日最多一条 Completion；
- 核心功能完全离线可用；
- 杀进程、重启和跨天不丢数据；
- 中断后 currentStreak 正确重启，totalCompleted 和 longestStreak 保留；
- 结束目标后历史保留，不能返回 ACTIVE 首页；
- 25 条 P0 验收用例全部通过。

---

## 3. V1 明确不进入开发的内容

- 多目标并行；
- 登录、注册和云同步；
- 补签、撤销历史完成记录；
- 图片、日记和长文本记录；
- 社区、好友、排行；
- 积分、金币、商城和复杂徽章；
- AI 对话或建议；
- 数量型、计时型和“坚持不做”型目标；
- 复杂周报、月报和趋势图。

发现以上需求时，记录到后续版本列表，不进入当前迭代。

## 4. 推荐工程结构

```text
app/
├─ data/
│  ├─ local/
│  │  ├─ entity/
│  │  ├─ dao/
│  │  ├─ database/
│  │  └─ datastore/
│  ├─ repository/
│  └─ mapper/
├─ domain/
│  ├─ model/
│  ├─ usecase/
│  └─ calculator/
├─ notification/
│  ├─ scheduler/
│  ├─ receiver/
│  └─ worker/
├─ analytics/
│  └─ AnalyticsTracker
├─ ui/
│  ├─ navigation/
│  ├─ component/
│  ├─ welcome/
│  ├─ create/
│  ├─ home/
│  ├─ records/
│  ├─ settings/
│  ├─ endgoal/
│  └─ history/
└─ core/
   ├─ date/
   ├─ design/
   └─ util/
```

约束：

- 日期计算集中在一个可测试模块，不散落在 ViewModel 中；
- 页面只消费状态和发送事件，不直接访问数据库；
- 提醒通过统一 Scheduler 接口管理；
- 埋点通过 AnalyticsTracker 接口封装；
- 业务数据不依赖网络。

# 5. 分阶段执行路径

## M0：工程准备与决策锁定

### 目标

建立可编译工程，锁定不会在开发中反复变化的基础约定。

### 执行任务

- [ ] 创建 Android Kotlin + Compose 工程；
- [ ] 建立版本管理仓库和基础分支策略；
- [ ] 配置 Debug / Release 构建；
- [ ] 接入静态检查、单元测试和 UI 测试基础依赖；
- [ ] 建立包结构；
- [ ] 确认应用 ID、工作名“一件”和图标占位资源；
- [ ] 建立日期服务 `DateProvider`，禁止业务代码直接散用系统时间；
- [ ] 建立 `NotificationScheduler` 和 `AnalyticsTracker` 空实现；
- [ ] 将三份产品文档和本执行路径放入项目文档目录。

### 退出条件

- Debug APK 可以成功构建和安装；
- 空白首页可以启动；
- 单元测试任务可以运行；
- 项目没有阻塞级编译警告或未决架构分歧。

---

## M1：主题、导航和本地数据骨架

### 目标

建立 11 个状态所需的公共能力，但暂不追求完整页面视觉。

### 执行任务

#### 设计基础

- [ ] 建立颜色 Token：背景、主文字、次级文字、未完成色、完成色、描边色；
- [ ] 建立字体层级、24dp 页面边距、52dp 主按钮和统一圆角；
- [ ] 建立 `AppScaffold`、`PrimaryButton`、`TopBar` 等基础组件；
- [ ] 处理状态栏和底部手势区 WindowInsets。

#### 数据模型

- [ ] 建立 Goal Entity / DAO；
- [ ] 建立 Completion Entity / DAO；
- [ ] 对 `(goalId, date)` 建立唯一约束；
- [ ] 建立 Settings DataStore；
- [ ] 保证同时最多一个 ACTIVE Goal；
- [ ] 建立 Repository 和领域模型映射。

#### 导航

- [ ] 定义欢迎、创建、首页、记录、设置、结束确认、结束结果和历史路由；
- [ ] 完成首次启动路由判断；
- [ ] 没有 ACTIVE 目标时进入创建页；
- [ ] 有 ACTIVE 目标时根据当天数据进入对应首页状态。

### 必须先写的单元测试

- Goal 只能有一个 ACTIVE；
- Completion 唯一约束；
- Settings 持久化；
- 首次启动、无目标和有目标的初始路由。

### 退出条件

- 数据可以写入并在杀进程后恢复；
- 主要路由可以通过占位页面走通；
- 主题和安全区在 360dp 基准设备上正确。

---

## M2：第一条可运行垂直闭环

### 目标

优先做出真机上可使用的最小闭环：创建一件事并完成一次。

### 实现顺序

#### 1. 欢迎页

- [ ] 仅首次出现；
- [ ] 点击“开始使用”记录 hasSeenWelcome；
- [ ] 返回键不能重新进入欢迎页；
- [ ] 不申请通知权限。

#### 2. 创建目标

- [ ] 目标名称必填并限制长度；
- [ ] 示例标签可填充输入框；
- [ ] 提醒默认开启、时间默认 20:00；
- [ ] 关闭提醒后隐藏或禁用时间选择；
- [ ] 点击“开始坚持”先保存 Goal；
- [ ] 只有提醒开启时才请求通知权限；
- [ ] 权限拒绝后目标仍创建成功，reminderEnabled=false；
- [ ] 创建成功后清理创建流程返回栈。

#### 3. 首页未完成

- [ ] 展示日期、目标名称、连续天数和 7 日进度；
- [ ] 今天未完成但昨天已完成时展示截至昨天的 currentStreak；
- [ ] “我完成了”是唯一主操作；
- [ ] 设置和记录入口热区不小于 44dp。

#### 4. 完成事务

- [ ] 点击后先防抖；
- [ ] 在本地事务中插入 Completion；
- [ ] 唯一约束冲突时不得重复累计；
- [ ] 成功落库后刷新统计；
- [ ] 成功落库后才上报 complete_success；
- [ ] 成功落库后才显示完成反馈。

#### 5. 完成反馈与已完成首页

- [ ] 完成反馈以首页 Overlay 实现；
- [ ] 约 1.2 秒自动关闭，也允许点击关闭；
- [ ] Overlay 不进入导航返回栈；
- [ ] 首页切换到绿色已完成状态；
- [ ] 当天不再显示完成按钮；
- [ ] 杀进程重新打开仍为已完成状态。

### 退出条件

- 真机可完成“首次打开 → 创建 → 完成 → 重开仍已完成”；
- P0 用例 TC-P0-001 至 TC-P0-006、017、018 通过；
- 完成一次只生成一条 Completion。

---

## M3：日期、统计、记录和中断

### 目标

建立产品最关键的数据可信度。

### 执行任务

#### 统计计算器

- [ ] 实现 todayCompleted；
- [ ] 实现 totalCompleted；
- [ ] 实现 currentStreak 唯一公式；
- [ ] 实现 longestStreak；
- [ ] 实现 durationDays；
- [ ] 实现 gapDays；
- [ ] 所有算法只依赖 LocalDate 和 Completion 日期集合。

#### 跨天

- [ ] App 进入前台时比较 lastOpenedDate；
- [ ] 00:00 后恢复页面时重新计算状态；
- [ ] 今天未完成、昨天已完成时保留截至昨天的 streak；
- [ ] 昨天未完成时进入 ACTIVE_INTERRUPTED；
- [ ] 今天新建的目标不进入中断状态。

#### 记录页

- [ ] 月历显示已完成、未完成和今天三种状态；
- [ ] 支持前后切换月份；
- [ ] 月历只读取 Completion，不修改数据；
- [ ] 展示当前连续、累计完成和最长连续；
- [ ] 返回原首页状态。

#### 中断页

- [ ] gapDays=1 使用“昨天没有完成”；
- [ ] gapDays>1 使用“有几天没有继续了”；
- [ ] 不突出连续 0 天；
- [ ] 完成后 currentStreak=1；
- [ ] totalCompleted 和 longestStreak 不被清空。

### 退出条件

- 至少使用 5 组跨天数据验证统计；
- 月历与 Completion 表逐日一致；
- P0 用例 TC-P0-007 至 TC-P0-010、019 至 TC-P0-021 通过。

---

## M4：设置、提醒和目标生命周期

### 目标

完成非日常主链路，使目标可以被修改、结束和保存。

### 执行任务

#### 设置

- [ ] 修改目标名称但不产生新 Goal；
- [ ] 修改名称不重置 startDate 和统计；
- [ ] 修改提醒时间先取消旧任务再建立新任务；
- [ ] 关闭提醒立即取消任务；
- [ ] 权限拒绝后可从设置再次引导开启；
- [ ] 接入历史、关于和隐私入口。

#### 通知

- [ ] 不申请精确闹钟特殊权限；
- [ ] 在所选时间附近触发，正常条件验收容差约 ±15 分钟；
- [ ] 提醒触发后按本地 reminderTime 安排下一次；
- [ ] 点击通知进入 ACTIVE 目标首页；
- [ ] 无 ACTIVE 目标时进入创建页；
- [ ] 手机重启后重调度；
- [ ] 系统时间或时区变化后重调度；
- [ ] App 更新后重调度；
- [ ] 确保重复广播不会生成重复任务。

#### 结束目标

- [ ] 结束确认默认强调“继续坚持”；
- [ ] 确认后 status=ENDED 并写入 endDate；
- [ ] 取消未来提醒；
- [ ] 保留全部 Completion；
- [ ] 清除 ACTIVE 首页返回栈；
- [ ] durationDays 按首尾自然日差 +1；
- [ ] totalCompleted=0 时结果文案为“这段记录已保存”。

#### 历史和下一件事

- [ ] 历史只展示 ENDED 目标；
- [ ] 从设置进入历史，返回设置；
- [ ] 从结束结果进入历史，返回结束结果；
- [ ] 开始下一件事后清除结束流程返回栈；
- [ ] 新旧 Goal 和 Completion 完全隔离；
- [ ] 无 ACTIVE 但存在历史时，创建页显示历史弱入口。

### 退出条件

- 设置、提醒、结束、历史和下一件事全部真机走通；
- P0 用例 TC-P0-011 至 TC-P0-014、022 至 TC-P0-024 通过。

## M5：埋点、适配、回归和发布

### 目标

完成质量封板，不新增功能。

### 执行任务

#### 匿名埋点

- [ ] 实现 AnalyticsTracker 接口；
- [ ] 事件载荷不包含 goalName 或用户输入；
- [ ] 无网络时不影响业务；
- [ ] complete_success 与数据库成功写入一一对应；
- [ ] 核对 PRD 中全部核心事件。

#### 适配与无障碍

- [ ] 小屏、360dp 主流屏和大屏三档走查；
- [ ] 状态栏和底部手势区无遮挡；
- [ ] 字体缩放后核心文字不裁切；
- [ ] 点击热区不小于 44dp；
- [ ] 颜色对比和状态不能只依赖颜色表达。

#### 自动化与回归

- [ ] 领域算法单元测试全部通过；
- [ ] Room 唯一约束和事务测试通过；
- [ ] 核心 Compose UI 测试通过；
- [ ] 执行《一件_APP_验收测试方案_V1.0.md》；
- [ ] P0 用例 100% 通过；
- [ ] P1 不存在影响发布的高优先级问题。

#### 发布准备

- [ ] 隐私政策入口可用；
- [ ] Release 构建无调试入口和测试数据；
- [ ] 版本号、应用名和图标正确；
- [ ] 生成可安装 Release 包；
- [ ] 保留测试报告和已知问题列表。

### 退出条件

- 25 条 P0 全部通过；
- 无阻塞级和严重级缺陷；
- 核心闭环在真机连续使用无数据丢失；
- Release 包可安装、启动和完成一次完整闭环。

## 6. 每个开发任务的完成定义

一个任务只有同时满足以下条件才能标记完成：

- [ ] 代码已实现并完成自测；
- [ ] 关键逻辑有单元测试或 UI 测试；
- [ ] 异常分支已处理；
- [ ] 杀进程和恢复场景已检查；
- [ ] 不违反 V1 产品边界；
- [ ] 对应验收用例通过；
- [ ] 没有新增未说明的数据字段、页面或权限；
- [ ] 文档与实现一致。

## 8. 每日执行节奏

每日开始：

1. 选择一个可以当天完成并验收的小任务；
2. 写或更新对应测试；
3. 实现功能；
4. 在模拟器和至少一台真机验证；
5. 对照验收用例记录结果；
6. 提交可运行代码。

每日结束前必须回答：

- 今天新增的功能是否真实落库；
- 杀进程后能否恢复；
- 是否影响 currentStreak、提醒或返回栈；
- 是否新增了 V1 范围外内容；
- 对应 P0 用例是否仍通过。

---

## 9. 最短可交付路径

如果资源紧张，严格按照以下顺序保交付：

```text
本地数据
→ 欢迎和创建
→ 首页未完成
→ 完成事务与已完成状态
→ 跨天和统计
→ 记录页
→ 中断状态
→ 结束与下一件事
→ 提醒
→ 历史
→ 埋点与视觉精修
```

可以降级动效和装饰，但不能降级：数据正确性、防重复、跨天、结束后历史保留和返回逻辑。

---

> V1 执行原则：先完成一个真实可用的闭环，再逐步增加状态；状态正确性永远优先于视觉动效。
