# 「一件」APP

## 前端调整与交互实现清单

> V1.0 · Android 客户端 / 前端联调用

> 产品原则：一次只坚持一件事。一天只记录一次。每天操作尽量控制在 3 秒内。

| 项目 | 内容 |
| --- | --- |
| 产品工作名 | 一件 |
| 设计方向 | A：温暖极简 |
| 基准画板 | 360 × 800（Android 主流机型适配基准） |
| Figma 文件 | https://www.figma.com/design/XEHhVWEe14BACPoGeKYD76 |
| 文档用途 | 后续由安卓前端/客户端开发按本文对现有原型进行精修、联调与验收 |

核心目标不是增加功能，而是把现有 11 个状态做完整、做统一、做顺畅。

## 1. 本轮调整范围与优先级

> 本轮不新增产品功能。所有开发资源优先用于：视觉统一、交互闭环、状态正确、Android 适配与体验细节。

| 优先级 | 定义 | 本轮要求 |
| --- | --- | --- |
| P0 | 必须完成 | 影响核心闭环、点击可用性、状态展示、数据正确性、Android 适配的问题。上线前必须全部通过。 |
| P1 | 建议完成 | 提升完成感、视觉一致性和产品质感的问题。建议在首版一并完成。 |
| P2 | 后续优化 | 非核心动画、进一步组件化、体验微调。不能阻塞 V1 上线。 |

### 1.1 P0 必改项总览

- 11 个页面/状态均统一为同一套 Android 视觉规范，不允许出现不同字号体系、不同圆角体系或不同主色。

- 所有可点击入口必须有明确点击热区，最小建议 44dp × 44dp；不能只让文字或细小图标本体可点。

- 首次进入 → 创建目标 → 首页未完成 → 完成 → 已完成 → 记录，主链路必须全程可走通。

- 设置 → 结束这件事 → 结果页 → 历史 → 开始下一件事，支链路必须全程可走通。

- 中断后连续天数重新计算，但累计完成/最长连续不能被清空。

- 当天只能完成一次；完成后不能再次重复计数。

- 所有页面适配状态栏、导航栏/手势区、异形屏安全区，不允许按钮贴底或被系统区域遮挡。

### 1.2 本轮明确不做

- 多目标并行、任务列表、目标分类。

- 社区、好友监督、排行榜。

- 积分、金币、商城、复杂徽章体系。

- AI 对话、AI 建议。

- 复杂数据图表、周报/月报。

- 强制登录、手机号注册。

- 照片打卡、长日记、补签体系。

## 2. 全局 UI 规范（开发统一执行）

| 项目 | 规范 | 开发验收 |
| --- | --- | --- |
| 设计基准 | 360 × 800 | 以 dp 体系实现，不能写死为仅适配单一设备分辨率。 |
| 页面背景 | #FDFBF7 | 所有主页面统一暖白底，不使用纯白大底替代。 |
| 主文字 | #141414 | 标题、主数据、核心操作使用。 |
| 次级文字 | #6B6B6B | 说明、标签、辅助信息使用。 |
| 未完成主色 | #FABF45 | 仅用于未完成态、主按钮、进度点等重要元素。 |
| 完成/成功色 | #59AD5E | 仅用于完成态、成功反馈、已完成日期。 |
| 分割/描边 | #E6E0D6 | 输入框、卡片、弱分割使用。 |
| 主按钮圆角 | 18dp | 全局一致；高度建议 52dp。 |
| 卡片/输入框圆角 | 16dp | 所有卡片与输入框统一。 |
| 页面左右边距 | 24dp | 核心内容保持同一纵向基线。 |
| 字体 | Noto Sans SC / 系统中文无衬线 | Android 实现优先系统字体或项目内统一字体，禁止页面间混用。 |

### 2.1 推荐字号层级

| 层级 | 推荐字号 | 用途 |
| --- | --- | --- |
| 大任务标题 | 28sp / Bold | 如“走路 20 分钟” |
| 关键数据 | 48–52sp / Bold | 连续天数 |
| 页面标题 | 20–24sp / Bold | 创建目标、记录、设置等 |
| 主要按钮 | 16–17sp / Bold | 我完成了 / 开始坚持 |
| 正文 | 14–16sp | 列表内容、结果说明 |
| 辅助文字 | 12–14sp | 日期、说明、标签 |

### 2.2 Android 适配要求（P0）

- 内容区域必须避开状态栏和底部手势区；使用 WindowInsets / Safe Area 思路处理。

- 360dp 宽度为基准，左右边距 24dp；更宽屏幕保持内容居中，不无限拉伸核心按钮。

- 小屏设备优先保证主按钮、任务标题、进度条可见；次要说明允许收缩间距，但不能裁切。

- 所有文本需支持系统字体缩放下的基本可读性，避免固定高度导致中文文字被裁切。

- 点击热区与视觉元素分离：齿轮、返回箭头、列表箭头等视觉尺寸可小，但可点击区域必须扩大。

## 4. 首页重点精修规范

> 首页是产品 80% 的体验。后续如果开发时间有限，优先把首页未完成态与已完成态做到最好。

### 4.1 首页未完成态

1. 顶部区域：状态栏由系统管理；内容首行展示日期，设置使用齿轮图标，不再使用“设置 ›”文字作为最终视觉。

2. 任务区域：“今天”弱于任务标题；任务标题使用 28sp Bold，保持单一主焦点。

3. 任务图标：使用简洁线性图标并放在浅暖黄色圆形/圆角底上；不要使用 Emoji 作为正式图标。

4. 连续天数：数字为视觉第二层级。今天未完成但昨天已完成时使用“已经连续完成 N 天”；今天完成后使用“连续第 N 天”；昨天也未完成时不突出“连续 0 天”。

5. 7 日进度：每一天必须同时有状态点 + 星期标签；未完成今天使用空心黄色描边。

6. 主按钮：“我完成了”高度 52dp，左右 24dp，黄色背景，深色/黑色按钮文字可优先于白字以保证视觉稳定。

7. 按钮底部说明“今天只做好这一件事”弱化显示；“查看记录”独立可点击。

### 4.2 首页已完成态

1. 任务标题、日期布局与未完成态保持完全一致，避免完成后页面结构突然跳动。

2. 任务图标保持原位；在中部使用绿色对勾作为完成反馈。

3. 主文案切换为“今天已完成”，成功色 #59AD5E。

4. 7 日进度全部按真实数据绘制；今天使用绿色圆环/双层点高亮。

5. 不再提供“我完成了”按钮，防止重复提交。

6. 可显示一张极轻的鼓励卡片，例如“太棒了！明天继续。”，但不能盖过核心任务信息。

## 5. 核心交互与状态逻辑

### 5.1 主流程

| 阶段 | 页面状态 | 下一步 |
| --- | --- | --- |
| 首次安装 | 欢迎页 | 点击开始使用 |
| 创建目标 | 输入目标 + 默认开启的提醒，可选择关闭 | 点击开始坚持 |
| 当天未完成 | 首页未完成 | 点击我完成了 |
| 完成反馈 | 首页 Overlay 成功卡片 | 约 1.2 秒自动关闭或点击关闭 |
| 当天已完成 | 首页已完成 | 查看记录或退出 |
| 第二天 | 重新进入未完成态 | 继续每日循环 |

### 5.2 状态字段（客户端至少需要）

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| goalId | String / Long | 当前目标唯一标识 |
| goalName | String | 如“走路 20 分钟” |
| startDate | Date | 目标开始日期 |
| reminderEnabled | Boolean | 提醒开关，创建时默认 true；权限拒绝或用户关闭后为 false |
| reminderTime | HH:mm | 每天提醒时间，默认 20:00 |
| todayCompleted | Boolean | 当天是否完成 |
| currentStreak | Int | 当前连续完成天数 |
| totalCompleted | Int | 累计完成天数 |
| longestStreak | Int | 历史最长连续天数 |
| completedDates | Set<Date> | 用于月历展示 |
| goalStatus | ACTIVE / ENDED | 当前是否仍在坚持 |
| gapDays | Int | 从昨天向前连续未完成的自然日数，最早统计到 startDate |
| durationDays | Int | 包含开始日和结束日/今天的持续自然日数 |

### 5.3 完成事件规则（P0）

- 同一自然日只能成功写入一次完成记录。

- 点击完成后先本地落库，再刷新 UI；避免动画完成但数据未保存。

- 若今日已完成，重复打开 App 不得再次显示可完成按钮。

- currentStreak：今天已完成时计算截至今天；今天未完成但昨天已完成时显示截至昨天；今天和昨天均未完成时为 0；中断后下一次完成从 1 开始。

- totalCompleted：每个完成日期只累计一次，永不因为中断归零。

- longestStreak：仅当 currentStreak 超过历史值时更新。

- durationDays：已结束目标为 endDate - startDate + 1，进行中目标为 today - startDate + 1，最小为 1；必须与 totalCompleted 分开展示。

- ACTIVE_INTERRUPTED：目标不是今天新建、今天未完成且昨天没有 Completion；连续漏掉多天只增加 gapDays，不新增状态。

### 5.4 日期边界

- 以用户设备本地自然日为准，00:00 进入新的一天。

- App 跨天仍在前台时，应在重新回到前台/页面刷新时检查日期变化并刷新 todayCompleted。

- V1 暂不支持补签历史日期。

- 用户修改系统时间可能造成边界异常，V1 可按设备日期处理，不需要增加复杂防作弊逻辑。

## 6. 提醒通知

| 项 | 要求 |
| --- | --- |
| 权限 | 首次需要通知时再请求系统通知权限，避免 App 一启动立即弹权限。 |
| 默认提醒 | 创建时默认开启，默认时间 20:00；用户可关闭，关闭时不申请权限。V1 仅一个固定提醒。 |
| 通知标题 | 今天那件事，做了吗？ |
| 通知内容 | 显示当前目标，例如：走路 20 分钟。 |
| 点击通知 | 有 ACTIVE 目标时进入当前首页；没有 ACTIVE 目标时进入创建页，不恢复旧目标。 |
| 已完成后 | 当天如已完成，后续同日提醒应取消/不再触发。 |
| 关闭提醒 | 设置关闭后立即取消已排程提醒。 |
| 时间精度 | 文案口径为“在所选时间附近提醒”；正常条件验收容差约 ±15 分钟，不申请精确闹钟特殊权限。 |
| 系统变化 | 手机重启、系统时间变化、时区变化或 App 更新后重新读取 ACTIVE 目标并调度。 |

## 7. 动效与反馈（P1，不阻塞核心功能）

| 动作 | 推荐效果 | 时长 |
| --- | --- | --- |
| 点击“我完成了” | 按钮轻微缩放 0.97 → 1.0 + 轻触觉反馈 | 120–180ms |
| 进入完成反馈 | 遮罩淡入 + 成功卡片轻微上浮/缩放 | 180–260ms |
| 成功对勾 | 缩放或描边出现 | 250–400ms |
| 反馈结束 | Overlay 淡出，首页呈现已完成状态 | 约 1.2s 后 |
| 页面切换 | 普通 Android 平滑转场即可，不做强烈左右飞入 | 180–250ms |

> 原则：完成感要有，但不要游戏化。动画不能影响用户快速退出 App。

## 8. 组件化建议（前端实现）

- AppScaffold：统一背景、安全区、页面左右间距。

- PrimaryButton：统一高度、圆角、禁用态、黄色/绿色两种状态。

- TopBar：返回、标题、设置入口统一点击热区。

- GoalHeader：今天 + 目标标题 + 图标。

- StreakBlock：当前连续天数与辅助说明。

- WeekProgress：7 日进度点 + 星期。

- StatsCard：当前连续 / 累计完成 / 最长连续。

- SettingRow：设置列表统一行高、箭头、分割线。

- SuccessFeedback：完成遮罩 + 成功卡片。

> 不要为 11 个页面分别写 11 套样式。页面越少越应该组件化，否则后续视觉调整成本反而更高。

## 9. 异常与边界场景

| 场景 | 预期处理 | 优先级 |
| --- | --- | --- |
| 目标名称为空 | 开始坚持按钮禁用；不允许创建空目标。 | P0 |
| 目标文字过长 | 输入限制建议 20 个中文字符左右；首页最多 2 行，超长截断或提示。 | P0 |
| 通知权限拒绝 | 目标仍可正常创建；设置页显示提醒未开启，引导后续开启。 | P0 |
| 当天重复点击完成 | 客户端防抖 + 数据层唯一日期约束，不能重复累计。 | P0 |
| App 被杀后重新打开 | 从本地状态恢复，不应回到欢迎页或丢失连续记录。 | P0 |
| 跨天 | 重新计算今日状态，昨日记录保留。 | P0 |
| 结束目标 | 历史数据保留，不物理删除。 | P0 |
| 无历史目标 | 我的历史展示空状态，不显示“清空历史”。 | P1 |
| 月历切月 | 切换月份只读取历史数据，不改变当前连续数据。 | P1 |

## 10. 开发调整顺序

| 阶段 | 任务 | 完成标准 |
| --- | --- | --- |
| 第 1 步 | 统一全局颜色、字体、圆角、边距、按钮组件 | 所有页面不再出现明显不同的视觉体系。 |
| 第 2 步 | 完成 03/05 两个首页状态 | 未完成/已完成切换正确，主按钮与进度正确。 |
| 第 3 步 | 完成创建与首次流程 | 安装后 30 秒内能创建并进入首页。 |
| 第 4 步 | 完成记录页 + 连续/累计逻辑 | 所有统计值和月历日期一致。 |
| 第 5 步 | 完成设置、结束目标、历史 | 支链路无死路、返回逻辑正确。 |
| 第 6 步 | 补完成反馈、中断状态、通知 | 状态完整，提醒可控。 |
| 第 7 步 | 多机型走查 | 至少小屏/主流/大屏三档无裁切与遮挡。 |

## 11. 最终验收清单

- [ ] 首次安装打开后只出现欢迎页，不出现登录/注册。

- [ ] 创建目标不超过 30 秒即可完成。

- [ ] 首页日常完成操作最多 1 次点击即可完成。

- [ ] 当天完成后不可重复增加累计完成次数。

- [ ] 第二天自动恢复为新的未完成状态。
