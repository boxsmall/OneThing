## 3. 页面与状态机

### 3.1 顶层状态

| 状态 | 进入条件 | 可执行动作 | 下一状态 |
| --- | --- | --- | --- |
| NO_GOAL | 首次安装或上一目标已结束 | 创建目标 | ACTIVE_UNDONE |
| ACTIVE_UNDONE | 存在 ACTIVE 目标，今日无完成记录 | 完成今天 / 查看记录 / 设置 | ACTIVE_DONE 或其他页面 |
| ACTIVE_DONE | 存在 ACTIVE 目标，今日已有完成记录 | 查看记录 / 设置 | 次日自动转 ACTIVE_UNDONE |
| ACTIVE_INTERRUPTED | 目标非今天新建、昨日无 Completion、今日未完成；附带 gapDays | 完成今天 | ACTIVE_DONE；currentStreak 从 1 开始 |
| ENDED | 目标被用户结束 | 查看历史 / 开始下一件事 | NO_GOAL 或历史列表 |

### 3.2 页面路由

| 来源 | 动作 | 去向 | 返回策略 |
| --- | --- | --- | --- |
| 欢迎 | 开始使用 | 创建目标 | 不可返回欢迎 |
| 创建目标 | 开始坚持 | 首页未完成 | 创建成功后返回键不回创建页 |
| 首页未完成 | 我完成了 | 首页 Overlay 完成反馈 → 首页已完成 | Completion 落库后显示；约 1.2 秒或点击关闭；不进入独立返回栈 |
| 首页 | 查看记录 | 坚持记录 | 返回原首页状态 |
| 首页 | 设置 | 设置 | 返回原首页状态 |
| 设置 | 我的历史 | 历史列表 | 返回设置 |
| 设置 | 结束这件事 | 结束确认 | 取消回设置；确认到结果页 |
| 结束确认 | 结束这件事 | 结束结果 | 不可回到 ACTIVE 首页 |
| 结束结果 | 我的历史 | 历史列表 | 返回结束结果 |
| 结束结果 | 开始下一件事 | 创建目标 | 清除结束流程返回栈；新目标创建后进入首页 |
| App 重启且无 ACTIVE 目标 | 自动路由 | 创建目标 | 有历史时展示“查看过去的坚持”弱入口 |

## 4. 本地数据结构

> V1 不需要账号体系。数据优先本地保存；如果后续加云同步，再在现有数据模型上增加 userId / syncStatus。

### 4.1 Goal（目标）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | String/Long | 是 | 唯一 ID |
| name | String | 是 | 单行，最多 20 个用户可见字符；去除首尾空白，不允许纯空白和换行 |
| startDate | LocalDate | 是 | 开始日期 |
| endDate | LocalDate? | 否 | 结束时写入 |
| status | ACTIVE / ENDED | 是 | 同时最多一个 ACTIVE |
| activeSlot | Int? | 否 | ACTIVE 固定为 1、ENDED 为 null；建立唯一索引 |
| reminderEnabled | Boolean | 是 | 创建时默认 true；权限拒绝或用户关闭后为 false |
| reminderTime | LocalTime? | 否 | 默认 20:00；关闭提醒时可保留上次选择供再次开启 |
| createdAt | DateTime | 是 | 创建时间 |
| updatedAt | DateTime | 是 | 最后修改时间 |

### 4.2 Completion（完成记录）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | String/Long | 唯一 | 记录 ID |
| goalId | String/Long | 索引 | 所属目标 |
| date | LocalDate | goalId + date 唯一 | 同一目标同一天只能有一条完成记录；不同目标可同日分别完成 |
| completedAt | DateTime | 必填 | 点击完成的具体时间 |

### 4.3 Settings（本地设置）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| hasSeenWelcome | Boolean | 是否已完成首次欢迎 |
| notificationPermissionState | Enum | UNKNOWN / GRANTED / DENIED |
| lastOpenedDate | LocalDate | 用于跨天刷新判断 |

## 5. 连续天数计算规则

- todayCompleted：当天是否存在 Completion(goalId, today)。

- totalCompleted：当前目标下 Completion 的去重日期总数。

- currentStreak：今天已完成时计算截至今天；今天未完成但昨天已完成时计算截至昨天；今天未完成且昨天也未完成时为 0；中断后的下一次完成从 1 开始。

- longestStreak：遍历该目标全部完成日期，取最长连续自然日序列长度。

- 结束目标不会删除 Completion；历史统计永远基于已保存记录。

- gapDays：仅用于 ACTIVE_INTERRUPTED，从昨天向前连续统计未完成的自然日数，最早统计到 startDate；如果从未完成过，则从 startDate 统计至昨天。连续漏掉多天仍使用同一状态。

- durationDays：已结束目标为 endDate - startDate + 1，进行中目标为 today - startDate + 1，包含首尾日期且最小为 1；与 totalCompleted 分开统计。

### 5.1 推荐实现约束

| 规则 | 实现要求 |
| --- | --- |
| 唯一完成 | 数据库层对 goalId + date 建唯一约束；UI 层同时防抖 |
| 唯一 ACTIVE | activeSlot 建唯一索引；ACTIVE=1、ENDED=null；生命周期切换使用事务 |
| 事务一致性 | 写 Completion 与刷新统计在同一事务/同一数据源完成 |
| 跨天 | onResume / App 回前台时比较 lastOpenedDate 与 today |
| 系统时间变更 | V1 以设备本地日期为准，不做复杂防作弊 |
| 中断判定 | startDate < today、today 无 Completion、yesterday 无 Completion；今天新建的目标不进入中断状态 |
| 持续天数 | 使用 LocalDate 自然日差值 + 1，不用小时数除以 24 |

## 6. 通知实现规则

| 场景 | 客户端处理 |
| --- | --- |
| 创建目标并开启提醒 | 默认时间 20:00；先保存目标 → 申请/检查权限 → 建立每日提醒 |
| 创建目标并关闭提醒 | 不申请通知权限，不建立提醒 |
| 权限拒绝 | 目标正常创建；reminderEnabled=false；提醒不调度；设置页可再次引导 |
| 当天已完成 | 取消/跳过当天剩余提醒 |
| 修改提醒时间 | 取消旧任务 → 新时间重新调度 |
| 关闭提醒 | 立即取消该目标的提醒 |
| 结束目标 | 取消该目标所有未来提醒 |
| 点击通知 | 有 ACTIVE 目标时进入首页；无 ACTIVE 目标时进入创建页，不恢复旧目标 |
| 调度精度 | 使用非精确系统提醒，不申请精确闹钟特殊权限；正常条件验收容差约 ±15 分钟 |
| 提醒触发后 | 按目标的本地 reminderTime 计算并安排下一次，避免周期漂移 |
| 手机重启 | 收到 BOOT_COMPLETED 后读取 ACTIVE 目标并重新调度 |
| 时间/时区变化 | 收到系统时间或时区变化后取消旧任务并重新调度 |
| App 更新 | 包替换完成后读取 ACTIVE 目标并重新调度 |
| 当天时间已过 | 创建或修改到已过去的时间时安排次日，不补发过期提醒 |
| 锁屏隐私 | 通知使用 VISIBILITY_PRIVATE，锁屏隐藏目标正文 |

## 7. V1 Analytics 与网络方案

> V1 不接入第三方 Analytics、Crash SDK、广告 SDK 或账号服务，不收集和上传数据。

保留 `AnalyticsTracker` 接口，Release 使用 `NoOpAnalyticsTracker`；Debug 仅允许输出本机结构化日志。Release Manifest 不声明 `INTERNET` 权限。

以下事件表仅作为未来候选，不进入 V1 实现和验收：

| 事件名 | 触发时机 | 关键参数 | 目的 |
| --- | --- | --- | --- |
| app_open | App 进入前台 | has_active_goal, today_completed | 基础活跃 |
| welcome_start_click | 点击开始使用 | - | 首次漏斗 |
| goal_create_success | 成功创建目标 | reminder_enabled, reminder_hour | 核心激活 |
| home_view | 进入首页 | state, current_streak | 状态分布 |
| complete_click | 点击我完成了 | current_streak_before | 完成意图 |

## 11. 开发沟通中的决策原则

- 遇到设计和实现冲突时，先保证“完成一件事”核心闭环，视觉动效可以降级，状态正确性不能降级。

- 遇到边界场景需要增加复杂配置时，V1 优先选择更简单且一致的规则。

- 所有新增入口都先回答：它是否能直接提高用户今天完成这件事的概率？如果不能，暂不加入。

- 如果一个页面可以通过状态变化解决，不新增新页面。

> V1 研发封板口径：用户能创建一件事、每天只完成一次、数据不丢、中断后还能继续、结束后历史仍在。
